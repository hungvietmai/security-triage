# CWE-78 safety-evidence pack v0.2 (worker copy)

The scan worker runs these queries as the adjudication step of the `command-injection-v0.2`
profile, on the CodeQL database the scan already created for Python.

| File | Source |
|---|---|
| `SafetyEvidence.qll`, `qlpack.yml` | Byte-identical copies of `experiments/owasp-bp-pilot/ql_v02/`, pinned by `FREEZE_v0.2_postformat.sha256` |
| `queries/cwe78_none.ql`, `queries/cwe78_all.ql` | Generated by the frozen `experiments/owasp-bp-pilot/ql_v02/gen.py` (LF line endings) |
| `codeql-pack.lock.yml` | `experiments/wave-c/pack-locks/v02.lock.yml` |

`experiments/tests/test_product_pack.py` fails if a copy drifts or if the generator no longer
produces these query bytes.

- `cwe78_none.ql` (`st/cwe-78/none`) is the default CodeQL command-injection flow, restated in
  this pack. It is the control: an alert of `py/command-line-injection` is compared with the
  evidence query only when this query reports the same location.
- `cwe78_all.ql` (`st/cwe-78/all`) adds every v0.2 safety-evidence barrier. Its alerts are a
  subset of the control's.
- A `py/command-line-injection` alert whose location the control reports and the evidence query
  does not is **refuted by safety evidence**. The worker then moves the candidate out of the
  main review list, unless another tool still claims a data flow there. The alert is kept with
  the rule and the evidence that filtered it; nothing is deleted.

The evidence mechanisms that apply to CWE-78 are constant branches, constant collection reads
and route-fixed path segments. They were developed on OWASP BenchmarkPython; no result on real
code exists for CWE-78. The evaluated scope of the v0.2 evidence layer is recorded in
`docs/research.md`.

Do not edit these files. A new evidence version needs a new pack directory and profile.
